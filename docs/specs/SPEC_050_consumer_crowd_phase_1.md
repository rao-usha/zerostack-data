# SPEC 050 — Consumer Crowd Phase 1 (Dataset Generation)

**Status:** Draft

**Plan:** [PLAN_062_addendum_1](../plans/PLAN_062_addendum_1_synthetic_consumer_crowd.md) — Phase 1

## Goal

Produce a 2,000-row teacher dataset of (consumer persona × business scenario) → 5 outcome variables, generated by GPT-4o, to seed the distilled consumer-response simulator described in PLAN_062 addendum 1. Phase 1 ships the dataset; Phase 2 distills it.

## Acceptance Criteria

- [ ] **Persona library:** 50 archetypes spanning demographic (age × income × geography) × psychographic (price sensitivity × brand loyalty × novelty-seeking) dimensions. Anchored on Pew typology + Nielsen Generations references.
- [ ] **Scenario library:** 40 templates across 6 categories (pricing 8 / product 8 / brand 8 / geographic 4 / competitor 6 / operational 6). Each parameterizable where applicable (e.g., pricing scenarios have a `magnitude` field).
- [ ] **GPT-4o teacher orchestrator:** async caller with retry-on-429/5xx, structured JSON output validation, response caching keyed by (persona_id, scenario_id, scenario_magnitude, brand_context_hash), per-call cost tracking.
- [ ] **Dataset builder:** iterates 50 × 40 = 2,000 (persona, scenario) cells; writes a parquet file with the schema in the plan; tracks per-row teacher_call_id for provenance.
- [ ] **Smoke test:** 5-cell mini-run produces valid parquet with all 5 outcomes populated, total cost ≤ $1.
- [ ] **Cost guardrail:** full 2,000-cell run completes ≤ $100 (2× nominal $60 budget).
- [ ] **Schema validation:** every row has all 5 outcome variables + 5 confidence values + provenance fields (teacher_model, teacher_call_id, generated_at) populated.

## Design Notes

### Persona structure

```python
# personas.py
PERSONAS: List[Persona] = [
    Persona(
        id=1,
        archetype="Suburban Mid-Career Family Spender",
        age_bracket="30-44",
        income_bracket="$50K-$100K",
        geography="suburban",
        price_sensitivity="medium",
        brand_loyalty="medium",
        novelty_seeking="low",
        anchor_reference="Pew Faith and Family-Centered + Nielsen Suburban Sprouts",
        prompt_summary="A 35-year-old suburban parent earning ~$75K, balancing brand familiarity against value, slow to adopt new products until peers do.",
    ),
    # ... 49 more
]
```

Personas are hand-curated to span the space, not full cartesian product. Each carries a `prompt_summary` (~30 words) that gets injected into the teacher prompt.

### Scenario structure

```python
# scenarios.py
SCENARIOS: List[Scenario] = [
    Scenario(
        id=1,
        category="pricing",
        event_type="price_up_10pct",
        magnitude=0.10,
        description="The brand they regularly buy raises its price by 10%, with no other changes.",
        outcomes_applicable=["purchase_intent", "wtp_delta", "sentiment", "wom_amplitude", "churn_probability"],
    ),
    # ... 39 more
]
```

Each scenario lists which outcomes are applicable. For example, "churn_probability" is only meaningful for existing-customer scenarios (pricing, operational change), not for "new product launch" (no existing relationship to churn from).

### Teacher prompt design

```
SYSTEM:
You simulate consumer responses to business scenarios for market-research purposes. 
You return ONLY a JSON object with the requested outcome variables. No prose.
Each outcome variable also has a 0-1 confidence value reflecting your certainty.

USER:
Persona: {persona.prompt_summary}
Scenario: {scenario.description}
Optional brand context: {brand_context or "generic consumer brand"}

Predict this persona's response across these outcomes:
- purchase_intent (0-1): likelihood of buying within 3 months given the scenario
- wtp_delta (-1 to 1): change in willingness to pay relative to baseline price
- sentiment (-1 to 1): emotional reaction to the scenario
- wom_amplitude (0-1): likelihood of telling others (positive or negative)
- churn_probability (0-1, null if not applicable): likelihood of switching away from this brand
- For each, a *_confidence (0-1)

Return JSON only.
```

Use OpenAI's structured-output mode (`response_format={"type": "json_schema", ...}`) for reliable parsing.

### Cost tracking

`teacher_runner.py` exposes:
```python
runner = TeacherRunner(model="gpt-4o", budget_usd=100.0)
result = await runner.run_cell(persona, scenario, brand_context=None)
runner.cost_so_far  # accumulator
runner.calls_so_far
```

`runner.run_cell` raises `BudgetExceededError` if the next call would push past `budget_usd`. This is the circuit-breaker — at $100 we cap the run rather than silently spending.

### Cache

Simple on-disk JSON cache keyed by `sha256(persona_id || scenario_id || magnitude || brand_context)`. Hit → return cached response, no teacher call. Useful for:
- Resuming after a partial-run failure
- Re-running the dataset build without paying again

### Smoke test

5 cells covering 5 different persona-scenario combinations spanning categories. Validates:
- End-to-end pipeline runs
- Parquet schema is correct
- Total cost ≤ $1 (5 cells × ~$0.03 + overhead)

### Full 2,000-cell run

Triggered by separate CLI:
```
python -m app.services.synthetic.consumer_crowd.dataset_builder --full --output data/synthetic_consumer/v1.parquet
```

Estimated wall time: 2,000 calls × ~3 sec each (with rate-limit padding) = ~100 minutes.
